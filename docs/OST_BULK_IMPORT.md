# 场景与回顾OST初步录入（阶段3）

本轮保持 `netease:<数字ID>` 主键，数字 `neteaseId` 和官方32位加密ID独立保存。只读元数据，不播放、下载或解析音源。

## 来源与可复现处理

- `data/sources/wiki-album-catalog.json` 为已查阅目录；24张专辑实际网页曲目表、修订号、原出处和逐曲作曲字段，经 `scripts/prepare-ost-sources.mjs` 清洗。
- 官方网易CLI0.1.7登录后，实际 search/get/tracks 均code200。搜索按确切专辑标题、详情按Wiki完整曲数选择；`data/sources/ost-bulk-source.json` 仅保留必要专辑/歌曲元数据，不包含账号、liked、请求trace或凭据。
- 中文、英文规范化匹配，不按数组位置赋ID。双方标题不同、Wiki空英文、同名版本和重复Disc caption均保留冲突记录。不能从艺人推定作曲，缺失作曲留null。
- 已缓存页面/官方响应仅在忽略的 `.local/bulk-wiki`、`.local/bulk-netease`。清洗可离线重跑，无需重复访问来源；他机已有净化source即可运行批次导入。净化脚本不会请求网络。
- 增量调查实际成功查阅 [深入风龙废墟](https://wiki.biligame.com/ys/深入风龙废墟)（所属地区蒙德、Boss特瓦林）及 [净琉璃工坊](https://wiki.biligame.com/ys/净琉璃工坊)（须弥、正机之神）。前者支持风龙废墟候选点；后者只支持须弥归属，缺附近点位不外推。其它追加页面404/567，未作为证据，未绕过限制。大量专辑原表为空或 `/`，不得从曲名补造出处。

## 挂载与校对边界

`scripts/lib/ost-associations.mjs` 比较来源出处与实际点位的【地理标题】，不把解锁任务中提到的远处城市当作点位所在城市，不从曲名推位置。分隔符表示国家—地区—地点链时优先叶子；多个并列地点保留多对多。完整点位说明仍供页面校对。

普通场景的精确候选先确定，野外补充随后排除已有精确普通场景点位，战斗与任务不占用普通场景覆盖。通用战斗按明确来源范围独立覆盖非城市点位。Boss或限定战斗找不到对应地点时保留目录，不全区散布。图中无对应地名、细音区缺证据时，只能按已知范围神像归档或保留无点位，不宣称真实BGM。

宽范围采用现有快照命名空间：蒙德初始野外对应蒙德源区；璃月初始野外对应璃月源区；稻妻野外对应三组地表岛区，独立渊下宫不套用；须弥雨林/沙漠分开；挪德大世界不套霜月。此范围是可审查候选规则，后续新增独立地图的通用BGM适用性仍需游戏核对。城市以地理标题匹配明确城市/港城/主要城镇，单列枫丹廷城内子区，不排除整个枫丹廷区郊野；村庄与野外营地不一概当城市。

金苹果群岛、琉形蜃境、希穆兰卡及对应回顾分碟零挂载；记录原出处和地区目录。悠悠度假村、霜月正常比对地图。仅部分点位说明含歌曲细地名，未匹配部分记录到审查清单，不能据此宣称地图实际缺少全部区域。

场景专辑明确国家可按专辑归属填写简洁国家；多地区回顾专辑无法确定的进入未定位目录。目录 `areaId/areaCode` 允许成对null，不伪造地图地区；数据库增量允许这两列null。网页显示“未定位”，已知国家不显示“位置未定（按…归档）”。

人工记录 `data/association-edits.json` 保持独立覆盖层。来源基线保留证据使“恢复来源”有效；应用人工remove后的页面/生产导出不恢复删除关系。重复导入按trackId+anchorId去重，不覆盖已有曲目、个人评价或关系证据。MySQL为增量副本，已有行保持，不把网页人工编辑当自动数据库同步。

## 批次

依次运行 `node scripts/import-ost-batch.mjs <批次>`：early、inazuma-sumeru、fontaine、natlan、northern、retrospective。每次包含此前批次，完成后验证/记录/提交/推送。脚本处理全来源的精确覆盖后再决定野外候选，结果按已录入专辑输出到 `data/review/ost-association-review.json`。该JSON含逐曲出处、类别、国家、目录代码、候选点位、缺失原因；页面按用户要求只展示原出处和点位说明，校对依据留在文件。

本轮新增关系全部pending，不参加路线自动选曲。没有音源播放验收，不将“可查询ID”当播放授权或浏览器播放成功。
