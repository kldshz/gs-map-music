# 工单模板（由 Codex 填写后派发）

## 身份与范围

- 工单编号：填写唯一编号。
- 所属阶段：填写用户已授权的阶段，不因派单自动推进阶段。
- 目标：一句话说明需要交付的结果。
- 模型与配置：Claude Opus 5-5；实际配置标识须明确；effort=high。不可换模型或降低配置。
- Codex 负责需求决策、任务拆分、审核、集成、检查、提交和推送；Claude 按本工单交付。

## 输入

列出必须阅读的需求、接口约定、代码文件与已有决定。实际调用时由 Codex 提供上下文内容或明确授权读取路径，不能要求用户转发。

## 输出与文件所有权

列出精确允许输出的文件、格式及接口；列出不可修改的文件。工单文本是协作范围约定，不代替操作系统访问控制。Codex 在 Claude 工作期间不编辑分配给它的文件。

## 约束

- 不改变技术栈，不新增业务需求，不编造来源或数据。
- 不操作 Git，不部署，不读取或输出凭据，不要求展示内部推理。
- 未知或依赖缺失时在结果中标记 blocked，不虚构完成。
- 返修以原工单编号追加修订号，明确期望行为、实际行为和最小改动。

## 验收

列出可执行检查与用户可观察行为；区分占位演示和真实功能。失败项必须明示。

## 结果报告

报告工单编号、完成状态、交付文件、修改摘要、执行过的检查、限制和待决项。Codex 核验报告与实际文件后决定接受或返修。
